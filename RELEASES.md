# Windows builds and releases

For a stable build, open the repository's **Releases** page and download the latest `Portal2VR-vX.Y.Z-win32.zip` plus `SHA256SUMS.txt`. Check the ZIP's SHA-256 against the checksum file, then extract the entire ZIP to a writable folder. Keep the folder layout intact and double-click `Portal2VR Launcher.exe`. The launcher is a standalone Windows executable; users do not need Python, Visual Studio, or a local build.

Close Portal 2 before using the launcher. Select the Portal 2 installation and its matching Steam installation, then use the launcher to apply or launch the mod. Keep the extracted folder, its launcher state, and its backups until you have used **Restore original game files**. The package contains the x86 mod DLL, OpenVR runtime DLL, configuration, action manifests, image, and license notices. The automated launcher build requires 64-bit Windows; the game-facing DLLs remain 32-bit. It does not include Portal 2, Steam, or SteamVR.

The native mod requires a Vulkan-capable graphics driver and the **Microsoft Visual C++ v14 Redistributable (x86)**, even on 64-bit Windows. Install the [latest supported x86 runtime](https://aka.ms/vc14/vc_redist.x86.exe) if needed. Its version must be at least as recent as the build tools used for the mod, as specified in [Microsoft's runtime guidance](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/). The launcher embeds Python; the package does not install system runtimes or graphics drivers.

Current game-build compatibility limits are recorded in [STABILIZATION_REPORT.md](STABILIZATION_REPORT.md). The verified local game binaries contain ambiguous required signatures; startup is intentionally refused until their correct targets are established.

Every successful push to `main` builds and tests a `v0.0.0` snapshot. The release job verifies its checksum and manifest, then repackages those exact payloads with an incremental stable version: the first version is `v0.1.0`, and each later main commit increments the highest stable patch version. A retry of the same commit reuses its version. Draft releases reserve versions while upload is in progress. Publishing checks that the Git tag, release target, ZIP manifest, and uploaded assets refer to the exact main commit. A retry whose rebuilt asset bytes differ from an existing draft or published asset stops for review; it never replaces published assets.

Pushes to `experimental`, pull requests, and manual workflow runs produce downloadable build artifacts under **Actions**. These are test builds labeled `v0.0.0` in their ZIP manifest and do not publish a GitHub Release. The `main` run also retains this snapshot artifact alongside its stable Release. Artifacts contain the ZIP, checksum, version marker, and frozen launcher self-test report. The build runs Windows Release/x86 and native tests, the full Python suite, and an extracted ZIP self-test against temporary fake game files. This automation does not establish behavior in a real Portal 2, SteamVR, or headset session.
